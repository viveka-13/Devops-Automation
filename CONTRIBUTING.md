# Contributing to TaskFlow Pro

## Workflow
1. Create a feature branch from develop.
2. Keep changes small and focused.
3. Commit with conventional commit messages.
4. Add or update tests where behavior changes.
5. Open a pull request against develop.
6. Ensure CI checks pass before merge.

## Branch naming
- feature/task-123
- fix/auth-expiry
- hotfix/urgent-security-fix
- release/v1.0.0

## Commit style
- feat: add new functionality
- fix: bug resolution
- test: add or update tests
- docs: documentation update
- chore: maintenance
- ci: pipeline changes

## Review expectations
- Review for correctness, security, and maintainability.
- Avoid committing secrets or environment files.
- Do not merge if lint or tests fail.
